# 英語リズム学習支援ツール(MVP)

`requirements.md` の 3.1 節(MVP)に対応する実装です。ブラウザ上でプロソディ(内容語/機能語、強形/弱形)を表示し、
学生が発話を録音して音量カーブ(RMS)を確認、音声認識との簡易比較フィードバックを得たうえで、
匿名化した数値データをサーバーに保存します。音声データそのものは保存しません(要件定義 3.4 節)。

## 構成

```
prosody/
├── requirements.md      # 要件定義書
├── backend/
│   ├── main.py           # FastAPI アプリ(API + フロントエンド配信)
│   ├── requirements.txt  # Python依存パッケージ
│   ├── prosody.db        # SQLite DB(初回起動時に自動作成、例文・提出データを保存)
│   └── media/audio/      # 管理者がアップロードしたモデル音声(初回アップロード時に自動作成)
└── frontend/
    ├── index.html         # 学生用画面
    ├── admin.html          # 管理者用画面(例文管理)
    ├── style.css
    ├── app.js              # 学生側: 録音・RMS解析・音声認識・送信ロジック
    └── admin.js            # 管理者側: 例文CRUD・モデル音声録音/アップロード
```

例文データは `frontend/sentences.js` のようなコード内配列ではなく、**SQLite DB(`sentences`テーブル)で管理**します。
初回起動時に既存の15文が自動的に登録されます。

## セットアップ

Python 3.10 以降が必要です。

```bash
cd backend
python -m pip install -r requirements.txt
```

管理者画面のログインパスワードを環境変数で設定します(未設定の場合は開発用デフォルト値 `changeme-admin` が使われるため、**本番運用前に必ず変更してください**)。

```bash
export ADMIN_PASSWORD="好きなパスワードに変更してください"
```

## 起動

```bash
cd backend
python -m uvicorn main:app --host 127.0.0.1 --port 8000
```

起動後、**Google Chrome** で `http://127.0.0.1:8000/` を開いてください(マイク録音・音声認識は
Web Speech API 依存のため Chrome 前提です)。

## 使い方(学生側フロー)

1. 学籍番号(匿名ID)を入力する。氏名は入力させない運用とすること。
2. 例文を選択し、プロソディ表示(内容語=大きく濃い文字、機能語=小さく薄い文字、弱形の強調表示)を確認する。
3. 「モデル音声を再生」でブラウザTTSの参考音声を聞く。
4. 「録音開始」でマイク入力を開始し、発話後「録音停止」を押す。
   - 録音中の音量(RMS)を50msごとにサンプリングし、停止後に平滑化してグラフ表示する。
   - 同時に Web Speech API で音声認識を行い、目標文と単語単位で比較する。
     - 内容語が認識されなければ「発音が不明瞭な可能性」、機能語が認識されなければ「弱形として自然な可能性」と表示する。
5. 録音完了・フィードバック表示と同時に、匿名ID・例文ID・音量カーブ(数値配列)・認識結果テキスト・タイムスタンプが
   自動的にサーバーへ送信される(送信ボタンの操作は不要)。録音した音声そのものはブラウザ内で破棄され、サーバーには送信されない。

## データの確認(教員向け・簡易)

MVPでは認証なしの簡易確認用エンドポイントのみを用意しています。授業外の環境で公開しないでください。

```
GET /api/submissions
GET /api/submissions?student_id=S23
GET /api/submissions?sentence_id=s01
```

## 例文の管理(管理者画面)

`http://127.0.0.1:8000/admin.html` (本番では `https://<デプロイ先>/admin.html`) を開くと、管理者用画面が使えます。
学生用画面(`index.html`)右上の「管理者画面 →」リンクからも移動できます。

- ログイン: `ADMIN_PASSWORD` に設定したパスワードを入力(ユーザー名は固定で `admin`)
- 例文一覧(画面左上): クリックすると右側に編集フォームが表示される
- 例文の追加・編集: 例文ID・例文テキスト・単語ごとの内容語/機能語・強形/弱形IPA・補足ノートを入力して保存
- 例文の削除: 編集中の例文を削除(登録済みモデル音声があれば一緒に削除される)
- **モデル音声の録音**: 例文を保存した後、「● 録音開始」でマイクから教員自身の発話を録音し、プレビュー確認後「アップロード」で登録できる
  - 登録すると、学生画面の「モデル音声を再生」ではブラウザTTSの代わりにこの録音が再生される
  - 未登録の例文は、これまで通りブラウザTTSが使われる

保存された例文はSQLite DBの `sentences` テーブルに、モデル音声は `backend/media/audio/` に保存されます。

## 発音診断(ベータ機能・デフォルト無効)

[Azure AI Speech の Pronunciation Assessment](https://learn.microsoft.com/azure/ai-services/speech-service/pronunciation-assessment-tool)
を使って、単語ごとの発音正確さ・リンキング(単語が連結されて聞こえなくなっている疑い=Omission)・
発音のずれ(Mispronunciation)などをスコア付きでフィードバックする機能です。

**⚠️ この機能を有効にすると、学生が録音した音声そのものがAzure(Microsoft)のサーバーに送信されます。**
これは現状の「音声データそのものは保存・送信しない」という設計方針(要件定義3.4節)からの変更にあたるため、
**必ず所属機関の倫理審査・情報セキュリティ担当への確認、学生への説明を済ませてから有効化してください。**
確認が済むまでは、環境変数を設定しないことで機能自体を無効化した状態(現在のデフォルト)にしておくことを強く推奨します。

### 有効化する場合

1. [Azure Portal](https://portal.azure.com/) で「Speech Service」リソースを作成し、キーとリージョンを取得する
   (無料枠 F0 あり。授業規模であれば無料枠内に収まる可能性が高いですが、利用量は各自ご確認ください)
2. 環境変数を設定する

   ```bash
   export AZURE_SPEECH_KEY="取得したキー"
   export AZURE_SPEECH_REGION="例: japaneast"
   ```

3. サーバーを再起動すると、学生画面に「発音診断(ベータ)」パネルが自動的に表示されるようになる
   (どちらか一方でも未設定なら、パネルごと非表示のまま)

### 仕組み

- 録音中、既存のRMS解析とは別に生の音声波形をブラウザ内でキャプチャし、録音停止時に16kHz・モノラルのWAVへ変換
- `POST /api/pronunciation-assessment` でサーバーへ送信 → サーバーがAzureへ中継 → 結果(総合スコア・単語ごとの正確さ/エラー種別)を返す
- 音声ファイルはサーバー側でも**一切ディスクに保存せず**、Azureへの中継のみに使い、レスポンスを返したら破棄する
- `GET /api/config` で `pronunciation_assessment_enabled` を返し、フロントエンドはこれを見てパネルの表示/非表示を切り替える

## Renderへのデプロイ

リポジトリルートの `render.yaml` を使って [Render](https://render.com/) にデプロイできます。

1. RenderでGitHubリポジトリを接続し、「Blueprint」からこのリポジトリを選択する
   (`render.yaml` が自動検出されます)。
2. デプロイ完了後、発行されたURL(`https://<service>.onrender.com/`)を**Google Chrome**で開く。

### 注意事項(本番運用前に必ず確認)

- **`ADMIN_PASSWORD` を必ず設定してください**。未設定だとデフォルト値 `changeme-admin` のままデプロイされ、
  誰でも例文の編集・削除・モデル音声のアップロードができてしまいます。RenderのDashboardの
  Environment設定で `ADMIN_PASSWORD` に推測されにくい値を設定してください
  (`render.yaml` では `sync: false` にしているため、Render側の管理画面で入力する必要があります)。
- **DBとモデル音声の永続化**: Renderの無料プランはファイルシステムが一時的で、再デプロイ・再起動のたびに
  `prosody.db`(提出データ・例文データ)と `backend/media/audio/`(録音したモデル音声)が消えます。
  データを残す場合はRenderの永続ディスク(有料)を追加するか、DB/オブジェクトストレージを外部化してください。
- **`/api/submissions` (GET) は認証なし**です。Renderにデプロイすると誰でもアクセスできる
  URLになるため、学外公開する場合は簡易Basic認証などのアクセス制御を追加することを強く推奨します。
- HTTPS化はRenderが自動で行います(要件定義5節の要件を満たします)。
- **`AZURE_SPEECH_KEY`/`AZURE_SPEECH_REGION` は倫理面の確認が済むまで設定しないでください**。
  未設定であれば「発音診断」機能は自動的に無効化されたままデプロイされます(上記「発音診断」の節を参照)。

## 未対応・今後の課題(要件定義 3.2/3.3/3.4 節を参照)

- 教員用ダッシュボード(提出状況の一覧表示)、ピッチ解析、CSVエクスポート等は Phase 2/3 で対応。
  - 例文の追加・編集UI(要件定義3.2節・項目11)は本バージョンで対応済み(管理者画面)。
- 音声データそのものの保存は行っていません(モデル音声=教員が録音した参考音声のみ保存対象で、
  学生の発話音声は引き続き保存しません)。学生の発話音声を保存する場合は倫理審査・インフォームドコンセントの整備が前提です。
  - 「発音診断」機能(ベータ)を有効化した場合のみ、学生の発話音声が外部サービス(Azure)に送信されます(保存はされません)。
    デフォルトでは無効です。詳細は「発音診断」の節を参照してください。
- `/api/submissions` (GET) は認証なしの簡易実装です。学外公開する場合はアクセス制御を追加してください。
- 本番運用時は HTTPS 環境でホスティングしてください(要件定義 5節)。

## 既知の制約

- 音声認識・マイク録音は Chrome 以外のブラウザでは動作しない場合があります(非対応時は警告バナーを表示)。
- 音量カーブと各単語の対応は、録音時間を単語数で均等分割した近似表示です。正確な単語境界にはフォーストアライメントが必要で、Phase 3の課題とします。
